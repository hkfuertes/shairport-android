# Handoff: Shairport

## State

The app is `com.hkfuertes.shairport` ("Shairport"). It is an AirPlay receiver for Android 8.1+ (API 27), arm64 and 32-bit ARM: classic AirPlay without root, AirPlay 2 (multi-room) with root for NQPTP only. The previous design (everything as root children of a `su` supervisor) was replaced on branch `feat/rootless-engine`; the old one was verified from an iPhone with both audio outputs, the new one so far with `avahi-browse` and a classic AirPlay sender (`cliraop`, silence) on the rooted POCO F1 (`40e396f`, Android 15, Magisk). Its settings can be changed over adb (README, "Configure from ADB"), and the advertised name defaults to Android's device name. A Kiosk Satellite plugin (`kiosk-plugin/`) manages it through that same adb interface, via Shizuku. The Echo (`G090LF1173731MAW`, Android 7.1) is below the floor and out of scope.

`diario.md` has the chronological log with measurements; read it before changing the engine lifecycle or Wi-Fi handling.

## Architecture decisions

Guiding rule (user, 2026-09-26): whatever Android can do, Android does; root only where nothing else works.

1. **Shairport runs as a JNI library in its own process.** `EngineService` (`android:process=":engine"`) calls `shairport_main()` on a thread (patch `shairport-sync/0003`, `android.c`). One run per process: Shairport's global state and its `exit()` both assume a fresh process, so `Engine.stop()` uses Shairport's own `exit_request()`, its atexit cleanup runs (mDNS goodbyes, AAudio closed), and a last handler ends the process with `_exit()` before other libraries' destructors. `ReceiverService` binds the engine to start it and unbinds to stop it, and waits until the `:engine` process is gone (SIGKILL after 5 s) before binding again: a new start must never run inside a process that is still exiting. An unexpected death restarts it after 30 s of uptime (not before, so a broken setup can't spin). Only `JNI_OnLoad` and `Java_*` are exported (version script), so the static OpenSSL/FFmpeg inside can't clash with the app process's own libraries. Considered: running the same executable as a child process of the app (Android 12+ limits those as "phantom processes"); rejected as less Android-like.
2. **Audio:** AAudio from the engine process (patch `0002`) gives Shairport a real `delay()`, which AirPlay 2 sync and multi-room need. The minimum is Android 8.1 (API 27, where Oboe starts trusting AAudio); the Android 7 `stdout` → `AudioTrack` pipe is gone. The player thread can't get realtime priority as an app ("Can not set realtime properties"): watch for underruns under load.
3. **mDNS through NsdManager:** Shairport's `android` backend hands each service type and its TXT records to `Engine.mdnsPublish()`. NsdManager has no TXT update, so a new TXT (AirPlay 2 group changes) unregisters and re-registers the service. The system responder follows address changes and drops the services with the process, so Wi-Fi changes no longer restart the engine. The app holds a `MulticastLock`, re-acquired after a reconnect (the POCO filters multicast again otherwise).
4. **AirPlay 2 is optional and the only use of root.** NQPTP binds UDP 319/320; neither kernel we had allows unprivileged low ports (`ip_unprivileged_port_start` is 4.11+). With the setting on, `ReceiverService` starts a root watcher through `su`: it kills leftover NQPTPs by name (`pidof`, never `pkill -f`, which matches the watcher's own command line), forces Wi-Fi hi-perf, runs NQPTP until its stdin reaches EOF (setting off, service stop, or the app dying), then stops both. Shairport uses `service_type = "auto"` and falls back to classic AirPlay when NQPTP is missing (su denied); with the setting off it is `"classic"` and nothing asks for root. The settings screen asks for `su` only when AirPlay 2 is turned on.
5. **NQPTP shared memory** lives in external app storage: root writes `/data/media/<user>/Android/data/<pkg>/files/nqptp-shm/nqptp` (Magisk root cannot write the app's `filesDir` under SELinux), the engine reads it through `/storage/emulated/<user>/…`. NQPTP's interface (SMI version 10) is read-only for clients and created 0644, so the app uid can map it. Verified on the POCO (64- and 32-bit).
6. **Wi-Fi:** with the screen off the POCO stops answering TCP/ARP (mDNS still works). The app's `WIFI_MODE_FULL_HIGH_PERF` lock prevents that up to Android 13; from 14 on app locks are screen-on only, so only AirPlay 2's root watcher (`cmd wifi force-hi-perf-mode`) helps there. Without root on Android 14+, the receiver may be unreachable with the screen off.
7. **Device ID:** apps can't read the MAC address, so `general.airplay_device_id` comes from `ANDROID_ID` (stable per device, user and signing key; locally administered unicast bits). `get_device_id()` no longer waits 10 s for a MAC (patch `0003`).
8. **Build:** one multi-stage Dockerfile from a clean clone: NDK, static deps for both ABIs, Shairport Sync and NQPTP at pinned commits plus our patches, the APK (the host's debug keystore as a BuildKit secret) and the plugin. No upstream source lives in the repository; `make src` exports the patched sources. Both ABIs are built; armeabi-v7a was verified on the POCO in 32-bit mode (`adb install --abi armeabi-v7a`), not on a 32-bit-only device.
9. **Start at boot** (no root): a `BOOT_COMPLETED` receiver starts `ReceiverService`, which is therefore a `connectedDevice` foreground service: Android 15 forbids starting `mediaPlayback` (and dataSync, camera, microphone…) ones from `BOOT_COMPLETED`. The type doesn't affect audio. With a secure lock screen the broadcast arrives after the first unlock. This replaced the Magisk `service.d` script (user decision, 2026-09-26, once the rest of the app no longer needed root).
10. **Kiosk Satellite plugin:** it only manages the app (user decision) and never runs the engine, which could not fit anyway (4 MB plugin limit; `libshairport_sync.so` alone is 5.7 MB; KS's Shizuku API is for bounded commands). It drives the adb interface through Shizuku (shell holds DUMP): `GET_STATUS` every 5 s (URL-encoded, so neither the plugin nor its JVM test needs a JSON parser), `CONFIGURE_SETTINGS`, and `am start-foreground-service` (ReceiverService is exported behind `android.permission.DUMP`, so adb/Shizuku start it without root). The app stays the source of truth: its values replace the plugin form, except while plugin changes are still queued.

## Open items

- **Not yet heard with an iPhone since the JNI change.** Verified: discovery (both services, full TXT), classic AirPlay playback of silence from `cliraop` with AAudio sync stats (error −0.07 ms). Still to check with an Apple sender: AirPlay 2 realtime and buffered streams, grouping from iOS/Home (TXT re-registration through NsdManager), multi-room next to another speaker, track skips, output device changes (Bluetooth), hour-long sessions.
- The Kiosk Satellite plugin was tested against a fake host (`kiosk-plugin/test`) and with the same `am` commands from `adb shell` on the POCO, not yet inside Kiosk Satellite.
- **Android → iPhone volume is deliberately not implemented** (a DACP `dmcp.device-volume` attempt was removed). Receiver-to-sender volume in AirPlay 2 is not in a stable Shairport release (upstream only declares `ap2_event_send_unit_volume_notification()`), and pushing volume from one speaker misbehaves in multi-room sessions. Add it once Shairport ships it stable.
- Shairport sync statistics are logged (`diagnostics.statistics`) until AAudio is proven; drop them afterwards.
- pyatv cannot exercise this build (AP2 uses NTP timing; classic RAOP sends L16, which this build fails to decode). `cliraop` from AirConnect (ALAC, `-a`) works for classic AirPlay; AirPlay 2 needs an Apple sender.
- Upstream ignores `general.port` at the pinned commit (always 7000 for AirPlay 2, 5000 for classic), so the app has no port setting.
